# Story 5 - The six panels, each from its real endpoint

## Goal
As the person running the Vyom deck, I open the console and see six panels - Health, Tasks, Agents, Quota, Containers, Actions - each fed by its own `/vyom/*` endpoint. Where something is real I see its data; where something was never written I see the words NOT BUILT and the reason why, never a blank list that would tell me "nothing is running" when the truth is "this was never built" (runbook 87). Each panel has its own render test, including the NOT BUILT case.

Assumption (non-blocking): "six" = Health, Tasks, Agents, Quota, Containers, Actions (`HealthPanel`, `TasksPanel`, `AgentsPanel`, `QuotaPanel`, `ContainersPanel`, `ActionsPanel` in `src/panels/Panels.tsx`). `SelfCheckPanel` (from `/vyom/me`) exists but is not one of the six; identity, tiles and `config_problem` belong to other stories.

## User journey
1. The person opens the console at `/console/` (or `npm run dev`) while logged in.
2. Every panel first shows a loading state, and each panel fetches only its own endpoint.
3. Health shows model, index freshness, answer quality and attention items.
4. Tasks shows document jobs, research packets and deferred archive copies.
5. Agents lists the agents read from `~/.claude/agents`.
6. Quota shows storage as a value and Usage as NOT BUILT with its why.
7. Containers shows NOT BUILT with its why (nothing is containerised).
8. Actions shows NOT BUILT with its why (`POST /vyom/act` returns 501).
9. If one endpoint fails, only that panel shows an error; the other five stay usable.

## Acceptance criteria
AC1 Exactly six panels render, titled Health, Tasks, Agents, Quota, Containers, Actions.
AC2 Health renders `model`, index freshness, answer quality and every attention item from `GET /vyom/health`.
AC3 Tasks renders three labelled groups - jobs, packets, deferred - from `GET /vyom/tasks`.
AC4 Agents renders one row per agent from `GET /vyom/agents`.
AC5 Quota renders storage from `GET /vyom/quota`, and when `usage.built` is `false` renders NOT BUILT plus the usage `why` in the Usage slot, never a number.
AC6 Containers, when `GET /vyom/containers` returns `built: false`, renders the text NOT BUILT and its `why`, and renders no list.
AC7 Actions always renders NOT BUILT with a why that names the 501 on `POST /vyom/act`; the panel issues no request to `/vyom/act` and offers no control that acts.
AC8 A `built: false` response from any panel renders the words NOT BUILT and the server's `why`; a missing `why` falls back to "not built".
AC9 A 403 response renders NOT BUILT with "not permitted for your role"; a 501 renders NOT BUILT with "not implemented yet".
AC10 While a panel's data is pending, that panel shows "loading…" and never NOT BUILT or an empty list.
AC11 A network or 5xx failure on one endpoint shows an error in that panel only, worded as a failure, never as NOT BUILT or "nothing here"; the other panels still render.
AC12 A built panel whose list is legitimately empty shows an explicit empty message (e.g. "no attention items"), never a blank area, and it is worded differently from NOT BUILT.
AC13 `src/panels/` contains at least one render test per panel (six panels), each panel with a built case, and every panel that can be `built: false` with a NOT BUILT case asserting the `why` text.
AC14 `npx vitest run src/panels` passes.
AC15 A 401 response redirects to `/vyom/login` instead of rendering a panel.
AC16 The panels make no request to any host outside the deck's own origin (intranet only).

## States
- **Loading:** the panel title with "loading…"; no data, no NOT BUILT.
- **Empty (built, no rows):** explicit line such as "no attention items", "no jobs", "no agents in ~/.claude/agents", "no containers reported" - visibly different from NOT BUILT.
- **Error:** panel-scoped failure message (HTTP status or network); other panels unaffected; never rendered as empty or NOT BUILT.
- **NOT BUILT:** heading "NOT BUILT" plus the server-provided `why` (Containers, Actions, Quota usage; any panel returning `built: false`).
- **Not permitted (403):** NOT BUILT with "not permitted for your role"; the panel shows no data.
- **Not implemented (501):** NOT BUILT with "not implemented yet".
- **Partial (Quota):** storage shown as a value while Usage shows NOT BUILT with its why.
- **Session expired (401):** browser sent to `/vyom/login`.

## Out of scope
- Making the console act: `/vyom/act` stays 501 (Phase 2 needs a named action list, role check and audit line).
- The ask box and `/vyom/ask`, tiles respecting `options`, and `config_problem` display from `/vyom/me`.
- Values with no endpoint (`vram`, `ram`, `latency`, `spend`, `brief`) rendering NOT BUILT (separate story).
- `SelfCheckPanel`, Founder vs COO/CTO tile differences, CSP checks, `ojas assets`, `ojas devcheck`, the app window at logon.
- Polling, auto-refresh, sorting, filtering or pagination of panel rows.
- Changing any server endpoint.
