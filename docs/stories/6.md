# Story 6 - Ask box with sources

## Goal
As the person running the Vyom deck, I type a question into the "Ask Vyom" box (`AskBox`, `src/ask/AskBox.tsx`), press Ask, and get Vyom's answer with the sources it used listed directly under it. I can see where an answer came from and open the source, so I can trust it or check it. When Vyom cannot answer, I am told so plainly - never a blank box that looks like "no answer exists".

## User journey
1. The person opens the console (`/console/` or `npm run dev`) while logged in.
2. They see the "Ask Vyom" card with an empty text box and a disabled Ask button.
3. They type a question; the Ask button becomes enabled.
4. They press Ask (or Enter). The button reads "Thinking..." and the box is locked.
5. The answer appears, and under it a "Sources" list: each source's title (a link), and its snippet.
6. They click a source title to open the document.
7. They ask another question; the previous answer and sources are replaced by the new ones.
8. If the ask fails, they see an error and can edit the question and try again.

## Acceptance criteria
AC1 The Ask button is disabled while the box is empty or whitespace-only, and pressing Enter on such a box sends no request.
AC2 Submitting a question sends exactly one `POST /vyom/ask` to the deck's own origin with `Content-Type: application/json` and a body containing the typed question.
AC3 While the request is pending, the button reads "Thinking...", and both the box and the button are disabled (no double submit).
AC4 On success the answer text is shown under the box.
AC5 Every entry in `sources` is shown under the answer, in the order returned, under a "Sources" heading, each with its title as a link to its `url` and its snippet.
AC6 Source links open in a new tab with `rel="noopener noreferrer"`.
AC7 A successful answer with an empty or missing `sources` list shows the answer plus an explicit line such as "no sources returned" - never a bare "Sources" heading with nothing under it, and never hidden silently.
AC8 A non-2xx response shows an error stating the HTTP status; a network failure shows a failure message; neither is rendered as an answer, as an empty answer, or as NOT BUILT.
AC9 A 501 from `/vyom/ask` shows NOT BUILT with "not implemented yet"; a 403 shows "not permitted for your role"; a 401 redirects to `/vyom/login`.
AC10 After an error, the box and button are usable again and the typed question is kept.
AC11 A new successful answer replaces the previous answer and sources; a new submit clears the previous error; an old answer is never shown next to a new error as if it were current.
AC12 A source with a missing or blank `title` still renders a usable link (falls back to its `url`), and a source `snippet` is rendered as plain text, never as HTML.
AC13 The ask flow makes no request to any host outside the deck's own origin, and the page shows no CSP errors when an answer with sources is displayed.
AC14 `src/ask/` contains tests for the answer-with-sources, empty-sources, error, pending and NOT BUILT cases, and `npx vitest run src/ask` passes.
AC15 In `npm run dev`, a real question against the running server shows its answer and its sources under it (👀 human check).

## States
- **Empty (nothing asked yet):** the card, the box with its placeholder, the Ask button disabled; no answer area, no Sources heading.
- **Loading:** button reads "Thinking...", box and button disabled; the previous answer, if any, does not pretend to be the new one.
- **Answer with sources:** answer text, then "Sources" with one entry per source (title link + snippet).
- **Answer with no sources:** answer text plus "no sources returned" - visibly different from an error.
- **Error:** "Error: HTTP <status>" or a network-failure message in the card only; the rest of the deck is unaffected; never worded as NOT BUILT or "no answer".
- **NOT BUILT:** on a 501 (or a `built: false` body with a `why`), the words NOT BUILT and the server's `why` (falling back to "not implemented yet") - never an empty answer.
- **Not permitted:** on a 403, NOT BUILT-style notice "not permitted for your role"; no answer, no sources.

## Out of scope
- `/vyom/act` (stays 501); the ask box never triggers an action. Acting is Phase 2.
- Conversation history, multi-turn memory, streaming answers, saving or exporting answers.
- Rendering the answer as markdown or rich text; ranking, editing or filtering sources.
- Deciding what the server may answer or which documents a role may see (the server decides).
- The other panels, tiles from `/vyom/me`, `config_problem`, and the app-window logon setup.
- Changing the styling/look of the card beyond what the states above need.
