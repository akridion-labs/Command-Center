# Story 12 - Self-check panel

## Goal
As the person running Vyom, I open the deck and see one "Self-Check" panel that tells me two things in plain words: is Vyom itself healthy, and what do I owe (reviews waiting, packets waiting, steps still open). These are the same facts `ojas selfcheck` prints, read from the `/vyom/selfcheck` endpoint (brief section 8), so I do not have to open a terminal to know what needs me. Until the endpoint answers, the panel says NOT BUILT and why; it never shows invented numbers.

Assumptions (non-blocking; brief section 8 was not readable here, so the field names are taken from the existing `SelfCheckPanel` in `src/panels/Panels.tsx`): the endpoint returns `{ built, own_health, reviews, packets, open_steps, attention[] }`. If section 8 names different fields, AC2-AC5 change with it.

## User journey
1. The person opens the console; the panels grid loads.
2. The Self-Check panel first shows "loading…".
3. The panel calls `/vyom/selfcheck` and shows "Own health: <value>".
4. Under "What you owe" they read Reviews, Packets and Open steps as counts.
5. If there are attention rows, they read them as a list, one row each.
6. They compare against `ojas selfcheck` in a terminal and see the same facts.
7. If Vyom's endpoint is missing or down, they see NOT BUILT with the reason, and the other panels are unaffected.

## Acceptance criteria
AC1 The Self-Check panel is titled "Self-Check" and is shown in the panels grid, fed only by `GET /vyom/selfcheck` (no other source, no internet call).
AC2 When the endpoint is built, the panel shows `Own health: <own_health>` exactly as returned.
AC3 The panel shows a "What you owe" heading and, under it, `Reviews: <n>`, `Packets: <n>` and `Open steps: <n>` with the returned values.
AC4 Each `attention` row is rendered as its own list item (name, title, id or label; with ` — status` when present).
AC5 The numbers and words on screen equal the endpoint's values and the `ojas selfcheck` output for the same moment; the panel adds, rounds and drops nothing.
AC6 Empty: with `built: true` and no owed items and no attention rows, the panel does not crash and says so in words (see States); a zero is shown as `0`, never hidden.
AC7 While the request is pending the panel shows "loading…"; it is replaced when the answer arrives.
AC8 If the request fails, the panel shows NOT BUILT with a reason naming the path (`/vyom/selfcheck unreachable`); it is not a blank box and not a stack trace.
AC9 If the endpoint answers `built: false`, the panel shows NOT BUILT and the endpoint's `why` text verbatim; this is the state until the endpoint exists.
AC10 One panel failing does not blank the others: Health, Tasks, Agents, Quota, Containers and Actions still render.
AC11 Many attention rows (50+) render in full, in order, without breaking the grid layout.
AC12 `npx vitest run src/panels/SelfCheck` passes (👀 human check: it showed NOT BUILT before the endpoint existed, and now renders the rows).

## States
- Loading: "loading…" under the "Self-Check" title.
- Empty (built, nothing owed, no attention rows): the panel shows the counts as 0 where given, and "no attention items" where an attention list is returned empty. If the endpoint returns no fields at all, the title shows with nothing under it - see the open point below.
- Error (network failure, 5xx, bad JSON): NOT BUILT, "/vyom/selfcheck unreachable".
- NOT BUILT (endpoint reports `built: false`): "NOT BUILT" plus the endpoint's why, e.g. "selfcheck down". Why: the endpoint or its data source does not exist yet.
- Not permitted: the panel has no role logic of its own. A 401/403 from the endpoint is treated as an Error (NOT BUILT, unreachable); the panel never shows partial data to someone who was refused. Open point for a person: should a refusal say "not permitted" instead of "unreachable"?
- Open point: an all-fields-missing `built: true` answer currently renders an empty panel; a person should decide whether it should say "nothing to report".

## Out of scope
- Fixing or acting on what is owed (no buttons, no approve/clear; `POST /vyom/act` stays 501).
- Building or changing the `/vyom/selfcheck` endpoint or `ojas selfcheck` itself.
- The other six panels, the tiles, identity, and roles/permissions.
- Auto-refresh or polling, notifications, history or trends.
- Styling changes beyond the existing panel look.
