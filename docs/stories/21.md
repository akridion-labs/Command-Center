# Story 21 - Model Console

## Goal
To provide operators with a centralized console that displays the status, health, and model information of the Vyom Command Center system, enabling them to monitor installed local models, view build loop evidence, and execute questions using specific models.

## User journey
1. Operator navigates to the Vyom Command Center console
2. Operator views the system's health and error status through the selfcheck endpoint
3. Operator examines detailed system checks via the doctor endpoint
4. Operator reviews available local models and their build loop evidence in the models endpoint
5. Operator selects a model from the picker to ask questions using the ask endpoint
6. Operator views release history through the static releases.json file

## Acceptance criteria
AC1 The `/vyom/selfcheck` endpoint returns system health information with level, area, text, and fix details.
AC2 The `/vyom/doctor` endpoint provides read-only system checks with name, ok status, cause, do command, detail, and fixed status.
AC3 The `/vyom/models` endpoint lists local models only, showing model names, default status, and build loop evidence including calls, minutes, slices_ok, and first_try percentages.
AC4 The `/vyom/ask` endpoint accepts a question with optional model selection, returning 400 error for unknown models.
AC5 The `/console/releases.json` file displays release history with version, date, since, commits, slices, fixes, and other details.
AC6 Model picker in the console lists all models from `/vyom/models` with default model marked.
AC7 Build loop evidence table shows minutes and first-try percentage for each model.
AC8 The console displays appropriate states for empty, loading, error, NOT BUILT, and permission-denied scenarios.

## States
Empty: Console loads with no data displayed, showing loading indicators
Loading: Console shows loading spinners while fetching data from endpoints
Error: Console displays error messages from failed API calls with retry options
NOT BUILT: Console shows "not built" message with explanation for each endpoint
Not permitted: Console displays access denied message when user lacks admin permissions

## Out of scope
- Cloud model integration (only local models are listed)
- Model management features (install, update, remove)
- Real-time monitoring updates beyond initial load
- User authentication and authorization flows (handled by existing system)
