# Story 13 - Conversational ask box

## Goal
As the person running Vyom, I use an ask box on the console that follows up on my earlier turns, like the `ojas` loop. When I post a question to `/vyom/ask`, the answer is shown with the tools it came from (self-check, weather) labelled under it. Anything the server has not built shows NOT BUILT with its reason, never an invented number.

Assumptions (non-blocking): the ask box lives in `src/ask/AskBox.tsx` beside the six panels in `src/Deck.tsx`; tile options come from `/vyom/me`; `vram`, `ram`, `latency`, `spend` and `brief` have no endpoint and are NOT BUILT; Founder and COO/CTO see different tiles.

## User journey
1. I open the console at `/console/`; the six panels load from their real endpoints and the ask box is shown with the prompt "Ask a question...".
2. I type a question (e.g. "Is it raining?") and send it.
3. While the answer is pending the ask box shows "loading…".
4. The answer appears with `sources` under it, each labelled by tool name (self-check, weather).
5. I type a follow-up; it is answered in the context of the previous turn, with no page refresh.
6. If `/vyom/me` reports a `config_problem`, I see that text near the sources.
7. If something is not built or unreachable, I see NOT BUILT and why.
8. I log in as Founder, then as COO/CTO, and see different tiles.

## Acceptance criteria
AC1 Posting a question sends it to `/vyom/ask` and shows the answer with `sources` listed under it, each labelled by tool name.
AC2 Tiles shown follow `options` from `/vyom/me` (convenience only; the server still decides).
AC3 When `/vyom/me` returns `config_problem`, its text is shown near the sources and never hides the ask box or the answer.
AC4 Every value with no endpoint (`vram`, `ram`, `latency`, `spend`, `brief`) shows NOT BUILT, never a number or 0.
AC5 After an answer, the ask box waits for the next prompt; a follow-up sends the previous turn with it, with no page refresh.
AC6 While `/vyom/ask` is pending the ask box shows "loading…", which is replaced when the answer arrives.
AC7 If `/vyom/ask` fails (network error, 500, bad JSON, 401/403) the ask box shows NOT BUILT with "/vyom/ask unreachable"; no answer or sources appear.
AC8 When an endpoint returns `built: false`, its tile shows NOT BUILT and the endpoint's `why` verbatim, never an empty list.
AC9 Founder and COO/CTO see different tiles, proven by logging in as each, not by reading `ROLE_OPTIONS`.
AC10 With all endpoints `built: true` and no question asked, the ask box shows the empty prompt and does not crash.
AC11 50+ sources all show their label and the layout does not break or cut the list short.
AC12 A `config_problem` with many rows is shown in full; only a 401/403 from `/vyom/me` is an error.
AC13 One panel failing does not blank the others: the other five panels and the ask box still render.
AC14 `npx vitest run src/ask` passes; a person confirms it shows NOT BUILT before the endpoint exists and sources after `/vyom/ask` is ready.

## States
- Empty: prompt "Ask a question...", no sources, no answer.
- Loading: "loading…" in the answer area until the reply arrives.
- Error: NOT BUILT with "/vyom/ask unreachable" (network error, 500, bad JSON); the other panels stay as they were.
- NOT BUILT: "NOT BUILT" plus the endpoint's `why` text (e.g. "vram not yet built"); never a number or an empty list.
- Not permitted: a 401/403 shows the same NOT BUILT / unreachable state; no partial data from the refused call is shown.
- Config problem: the `config_problem` text is shown near the sources; the ask box still works.

## Out of scope
- `/vyom/act` stays 501; making the console act is Phase 2 (named action list, role check, audit line first).
- Building or changing `/vyom/ask` or the `ojas ask` logic on the server.
- Styling beyond the existing panel look.
- Polling or auto-refresh for new answers.
- Saved history or trends across sessions.
