# Story 20 - Doctor Panel

## Goal
To provide administrators with a comprehensive view of Vyom's health and errors through a dedicated doctor panel, enabling them to quickly identify issues, understand their causes, and take corrective actions using the `ojas doctor --fix` command.

## User journey
1. Administrator navigates to the Vyom Command Center
2. Selects the Doctor panel from the navigation menu
3. The panel displays the current health status of Vyom
4. If any issues are found, the panel shows detailed information about each check
5. For each failing check, the panel provides the cause and the command to fix it
6. Administrator can see which checks have been automatically fixed
7. The panel also shows model information and release history

## Acceptance criteria
AC1 The doctor panel displays a list of system checks with their status (ok/warn/bad/owe)
AC2 For each failing check, the panel shows the cause and the command to fix it (do)
AC3 Checks that have been automatically fixed are indicated as such
AC4 The panel fetches data from the `/vyom/doctor` endpoint using `api.ts`
AC5 The doctor panel is accessible only to users with admin role
AC6 The panel displays model information including names, default status, and build loop evidence
AC7 The panel shows release history from the static file `/console/releases.json`
AC8 The panel handles loading states gracefully
AC9 The panel displays appropriate error messages when data fetching fails
AC10 The panel shows NOT BUILT state with an explanation when the feature is not enabled

## States
Empty: Panel loads and shows a loading indicator or empty state message
Loading: Panel displays a spinner or skeleton while fetching data from endpoints
Error: Panel shows an error message with details about what went wrong during data fetch
NOT BUILT: Panel displays a message indicating the doctor feature is not built, along with the reason why
Not permitted: Panel shows a message indicating insufficient permissions to access the doctor panel

## Out of scope
- Actual implementation of `ojas doctor --fix` command (covered in separate task)
- Full model management features beyond display and selection
- Detailed error logging or debugging information beyond what's shown in the doctor panel
- Integration with external monitoring systems
