# Story 12b - End-to-end and visual tests

## Goal
As the person who approves each slice, I want the console driven in a real browser the way I use it - every panel, the ask box and the tiles - against the BUILT app with the deck mocked, so a page that unit tests call green but that renders blank, wrong or calls the internet is caught before I see it. I also get screenshots at 1280 and 1920 wide; the first set is the baseline I approve with `npx playwright show-report`. Nothing here changes what the app does.

Assumptions (non-blocking): panel titles are those in `src/panels/Panels.tsx` (Health, Tasks, Agents, Quota, Containers) plus Self-Check (`src/panels/SelfCheck.tsx`); "six panels" in spec 5.8 means the six that read `/vyom/*` today, and the count is confirmed against the running app when the tests are written. Exact endpoint list, `/vyom/me` shape (`options`, `config_problem`) and the `/vyom/ask` shape (`answer`, `sources`) come from brief section 8 and `src/api`, `src/ask/AskBox.tsx`, `src/tiles/`.

## User journey
1. The person runs `npx playwright test --grep-invert @visual`; it builds the app, serves it at `http://localhost:4173/console/` and runs Chromium with no login, network or live deck.
2. They see a pass/fail list per spec: panels, ask, tiles, intranet.
3. They run `npx playwright test --grep @visual`; screenshots are taken at 1280x800 and 1920x1080.
4. They open `npx playwright show-report` and look at each screenshot.
5. On the first run there are no approved images, so the new screenshots are the baseline; they approve them.
6. On later slices a screenshot difference is shown as "UI changed" for them to look at; it never silently rewrites a baseline.

## Acceptance criteria
AC1 `playwright.config.ts` sets `testDir: 'e2e'`, one chromium project, `baseURL` `http://localhost:4173/console/`, and a `webServer` that runs `npm run build && npx vite preview --port 4173 --strictPort` and waits on that URL (`reuseExistingServer: true`).
AC2 `package.json` has `"e2e": "playwright test --grep-invert @visual"`, and `npx playwright test --grep-invert @visual` runs no `@visual` test.
AC3 `e2e/fixtures.ts` answers every `/vyom/*` request via `page.route` from JSON files in `e2e/data/`, with one BUILT and one NOT BUILT (`{built:false, why}`) file per endpoint; a `/vyom/*` request with no fixture fails the test loudly rather than reaching a network.
AC4 With all endpoints BUILT, the six panels each render with their title and content from the fixtures (`e2e/panels.spec.ts`).
AC5 With an endpoint NOT BUILT, that panel shows "NOT BUILT" and its `why` text verbatim, never an empty list or blank card; the other panels are unaffected.
AC6 Ask (`e2e/ask.spec.ts`): typing a question and submitting sends a POST to `/vyom/ask` carrying that question, and the mocked answer and its sources appear under the answer.
AC7 Tiles (`e2e/tiles.spec.ts`): the tiles shown equal the `options` in the mocked `/vyom/me`; a different `options` gives a different set of tiles.
AC8 When `/vyom/me` returns `config_problem`, it is visible on the page; when it is absent, nothing of the kind is shown.
AC9 Intranet (`e2e/intranet.spec.ts`): the test records every request the page makes while loading and while using the panels, ask box and tiles, and fails if any request host is not `localhost` or `127.0.0.1`. The failure message names the offending URL.
AC10 The intranet test really can fail: a deliberate external request (e.g. a page-injected fetch to `https://example.com`) makes it red. Proof that it is not vacuous.
AC11 `e2e/visual.spec.ts` is tagged `@visual` and calls `toHaveScreenshot()` at 1280x800 and at 1920x1080, animations disabled, the three.js canvas masked so the background does not cause noise.
AC12 A repeated `@visual` run on an unchanged app produces no difference (screenshots are stable across two consecutive runs).
AC13 The e2e run is the same every time: no test depends on wall-clock, live data, login or the internet, and the suite passes twice in a row.
AC14 No test edits or overwrites a baseline by itself; baselines change only through an explicit update the person approves.
AC15 Human check 👀: `npx playwright show-report` opens, and the first screenshots at both widths are looked at and approved as the baseline.

## States
- Empty: an endpoint that is BUILT but returns empty lists shows each panel's words ("no agents in ~/.claude/agents", "no containers reported", "no attention items"), never a blank card.
- Loading: before the mocked answers arrive, panels show "loading…"; tests wait for the settled state, not a fixed sleep.
- Error: a `/vyom/*` request that fails (fixture returns 500 or aborts) shows the panel as NOT BUILT with "/vyom/<name> unreachable", not a blank box or stack trace; other panels still render.
- NOT BUILT: `{built:false, why}` shows the words NOT BUILT and the `why` exactly as given, for each panel that has such a fixture.
- Not permitted: a 401/403 from a mocked endpoint is shown as an error (NOT BUILT, unreachable) and no partial data appears; the suite does not log in. Open point for a person: should a refusal say "not permitted"?
- Test-run states: browser not installed -> the run stops with Playwright's own "run npx playwright install" message; port 4173 busy -> `--strictPort` fails at once with a clear error, it does not pick another port; no baseline yet -> first `@visual` run writes candidates and is reported, not passed silently.

## Out of scope
- Any change to app code, styles or components; only `e2e/`, `playwright.config.ts`, `package.json` script and dev dependency are added.
- Running the browser download (`npx playwright install --with-deps chromium`); the person does that once.
- Firefox, WebKit, mobile viewports, other widths than 1280 and 1920.
- Testing against the live deck, real login, or real `/vyom/act` (stays 501).
- The runner's `ojas build --approve/--reopen` flow and the "UI changed" 👀 marking; this story only produces the screenshots it compares.
- Full-page pixel checks of the three.js scene itself (masked).
