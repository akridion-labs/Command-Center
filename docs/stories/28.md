# Story 28 - Model Fitness in Console

## Goal
To provide visibility into the fitness status of each model in the Vyom Command Center, enabling team members to quickly identify which models are ready for use and why any given model might be unfit.

## User journey
1. Navigate to the Vyom Command Center dashboard
2. Locate the "Models" panel within the deck interface
3. Observe the fitness status indicators next to each model
4. Review the detailed reasons for any unfit models
5. Understand which tests are associated with each model

## Acceptance criteria
AC1. Each model in the console displays a `fit` status (✓ or ✗) indicating whether it can perform the build loop's work
AC2. For unfit models, a `fit_why` field shows the specific reason why the model is not fit
AC3. Models without fitness data show "not checked" as their fit status
AC4. Tests for each model are displayed in the console under the respective model
AC5. The console handles loading states, empty results, errors, and permission denials gracefully

## States
- Empty: Shows "No models found" message when no models exist
- Loading: Displays loading spinner while fetching data from `/vyom/models`
- Error: Shows error message with details when API request fails
- NOT BUILT: Displays the reason why the endpoint is not built (e.g., "not permitted for your role")
- Not permitted: Shows "Not permitted for your role" when access is denied
- Fit model: Displays ✓ with associated tests
- Unfit model: Displays ✗ with `fit_why` explanation and associated tests

## Out of scope
- Model fitness calculation logic (handled by ojas models-check)
- Detailed model configuration UI
- Integration with external tools beyond the `/vyom/models` endpoint
- Performance optimization for large numbers of models
