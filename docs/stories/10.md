# Story 10 - three.js background

## Goal
As the person watching the Vyom deck (often over RDP), I see a subtle, slow-moving 3D particle field behind the tiles, so the console feels alive. The panels stay the product: they render first, stay readable and clickable on top of the scene, and the deck is fully usable when the scene is absent (no WebGL, reduced motion, or a hidden window). The scene never makes the RDP session stutter and never competes with Ollama for the GPU.

## User journey
1. The person opens the built console (`npm run build`, then the served `dist/`).
2. The tiles and panels appear immediately, before any 3D.
3. A moment later a faint particle field fades in behind them and drifts slowly.
4. They use the deck (Ask box, tiles, links) with the scene behind; nothing is covered or blocked by it.
5. They switch to another window or tab; the scene stops animating. They come back; it resumes.
6. They view the same console in the RDP window; it stays smooth and the panels respond normally.
7. On a browser with no WebGL, or with "reduce motion" on, they see the plain deck with no background and no error.

## Acceptance criteria
AC1 `npm run build` succeeds with no TypeScript errors and emits `dist/` (👀 human check that the built deck renders).
AC2 `three`, `@react-three/fiber` and `@react-three/drei` (as used) are installed from npm and bundled into `dist/`; `@types/three` is a dev dependency; `npm install` needs no `--force` / `--legacy-peer-deps`, and the installed R3F peer range accepts the installed React.
AC3 No built file and no `index.html` loads a script, font or asset from a CDN or any other origin; the scene makes no network request at all.
AC4 The three.js code is a separate lazy chunk: the entry bundle does not contain three.js, and the panels render without waiting for that chunk to load.
AC5 When WebGL is unavailable, `Background` renders nothing (no canvas, no error, no console error), and every panel still renders and works.
AC6 When `prefers-reduced-motion: reduce` matches, `Background` renders nothing and no scene chunk is requested.
AC7 If the scene chunk fails to load or the WebGL context is lost or throws, the deck still renders and works; the failure does not blank the page or unmount the panels.
AC8 The canvas is fixed behind content (`z-index` below the panels), `pointer-events: none`, and `aria-hidden="true"`: every tile, link and the Ask box remain clickable and keyboard-focusable, and the canvas is not in the tab order or announced by a screen reader.
AC9 Panel text stays readable over the scene: the scene is low opacity/contrast, and no panel loses its contrast-checked colours.
AC10 The scene is light: `frameloop="demand"`, `dpr` 1, no post-processing, no antialiasing, and the point count is at most 500.
AC11 While `document.hidden` is true the scene schedules no frames (its tick timer is cleared); when the window is visible again it resumes; unmounting clears the timer and the `visibilitychange` listener.
AC12 The scene's tick rate is throttled (at most 30 frames per second) so it does not run at display refresh rate.
AC13 Over RDP the deck does not stutter: the tiles respond to clicks and typing without visible lag while the scene runs, and the scene stays smooth or degrades to still (👀 human check in the RDP window, not on a laptop).
AC14 With the browser on the server, running the scene does not measurably slow a running Ollama answer (👀 human check: `nvidia-smi` GPU use with the deck open vs closed, Ollama tokens/s within a small margin).
AC15 `src/scene/` has tests for WebGL-absent, reduced-motion, visible/hidden pause-and-resume, and cleanup on unmount, and `npx vitest run src/scene` passes; the existing full suite still passes.
AC16 No company data, vault text or endpoint names appear in the scene code or in anything sent to a cloud model when choosing the library.

## States
- **Empty:** not applicable - the scene has no data. With the scene absent the deck looks exactly like before this story.
- **Loading:** while the scene chunk downloads, only the panels are shown; there is no spinner, placeholder or layout shift.
- **Error:** chunk fails to load, WebGL context lost, or a render error: the background silently disappears, panels stay; at most one console warning, no error banner.
- **NOT BUILT:** not a panel state. If the scene is not installed/built in a given deployment, the deck shows the panels with no background - it never shows a "NOT BUILT" tile for decoration, and the panels' own NOT BUILT tiles (`src/NotBuilt.tsx`) render unchanged.
- **Not permitted:** not applicable - the scene reads no data and calls no endpoint, so a 401/403 from a panel never affects it.

## Out of scope
- Any new panel, data, or endpoint; no change to panel content or to the tile layout.
- Post-processing, shadows, models/textures, audio, mouse-follow interaction, or a scene that reacts to data.
- Motion, GSAP, recharts, lucide, shadcn (approved elsewhere; not used by this story).
- A user-facing toggle to turn the scene off (the browser's reduce-motion setting is the switch).
- SSR, a router, i18n, a CDN build of three.js.
- Tuning for a GPU other than the RTX 5070 box and the RDP session.
