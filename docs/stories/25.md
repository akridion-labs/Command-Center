# Story 25 - Night report panel

## Goal
As the founder checking the deck in the morning, I want one panel that shows the last night/day report from the build loop as plain text, with the time it was written at the top, so I can read what happened overnight without leaving the Deck. The report is always shown as text: its `#`/`##` headings and lines are visible as written and never turned into HTML.

## User journey
1. The founder opens the Deck (signed in as admin).
2. The Night report panel sits in the Deck grid next to the other panels (built with `PanelShell`, `NotBuilt` for non-built states).
3. While `GET /vyom/night` is in flight, the panel says it is loading.
4. When the report arrives, the founder sees the report time (`at`) at the top, then the report body line by line, headings included as plain text.
5. If the server has no report yet, the panel says so instead of showing a blank box.
6. If the server says `built: false`, the panel shows NOT BUILT with the server's `why`.
7. If the session has expired (401), the founder is sent to login.
8. If the founder's role is not allowed (403), the panel shows NOT BUILT "not permitted for your role".
9. If the report text contains HTML, the founder sees the tags as literal text.

## Acceptance criteria
AC1 - The panel fetches `/vyom/night` through `api.ts` `get()` and shows the `markdown` body as plain text, keeping every `#`/`##` heading line and line break visible as written.
AC2 - The report time (`at`) is shown at the top of the panel, above the body, in monospace.
AC3 - The body is rendered as text only: markup such as `<b>x</b>` or `<script>` in the report appears literally and is never interpreted; no `dangerouslySetInnerHTML` is used.
AC4 - While the request is in flight the panel shows a loading state, with no body and no time.
AC5 - When `built: true` but the report is empty (no `markdown`), the panel says plainly that there is no night report yet, rather than showing an empty box.
AC6 - When `built: false`, the panel shows NOT BUILT with the response's `why` text (via `NotBuilt`), never an empty body.
AC7 - When `/vyom/night` returns 403, the panel shows NOT BUILT "not permitted for your role".
AC8 - When `/vyom/night` returns 401, the app goes to login (the house behaviour of `get()`); the panel shows no report and no error text of its own.
AC9 - A failed request that is not 401/403 (network error, 500) shows an error message in the panel and does not look like "no report yet".
AC10 - The e2e harness has a fixture for `GET /vyom/night`, so the Deck loads with the panel without a "no fixture" refusal.

## States
- **Loading** - "loading" indicator inside the panel; no time, no body.
- **Built with a report** - time (`at`) in monospace on top, body below as plain text with headings visible as `#`/`##` lines.
- **Built, zero rows** - "No night report yet"; no time shown.
- **NOT BUILT** - the `why` from the server, shown as text through `NotBuilt`.
- **Not permitted (403)** - NOT BUILT with "not permitted for your role".
- **401** - redirected to login; the panel shows nothing of its own.
- **Error (other failure)** - an error message, distinct from the empty state.
- **Long report** - the body scrolls inside the panel and does not stretch the Deck grid.

## Out of scope
- Rendering the report as HTML or markdown formatting (bold, lists, links).
- Auto-refresh, scheduling or picking older reports.
- Editing or downloading the report.
- Showing `file` (the report path) beyond optionally as small text; the `at` time is the required header.
- Copy buttons (this endpoint returns no `next` command).
