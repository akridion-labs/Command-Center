# Story 27 - safe links

## Goal
As someone using the deck, I want a web address that the server sends me to become a clickable link only when it is safe (a relative path, or http(s) on this deck's own origin). Anything else - another host, `javascript:`, `ftp:`, `mailto:`, `data:` - shows as plain text with its address visible, so I can read it but a click cannot send me off the intranet or run script. One shared helper, `src/safeUrl.ts`, makes this decision for every place that renders a server URL (today the Ask box sources in `src/ask/AskBox.tsx`; any panel added later reuses the same helper).

## User journey
1. I open the Deck and ask a question in the Ask box.
2. The answer lists sources, each with a title and a URL from the server.
3. A source whose URL is relative or on this deck's origin shows as a link; I click it and it opens.
4. A source whose URL points elsewhere (or uses another scheme) shows as plain text - the title, with the address visible - and nothing is clickable.
5. A source with a malformed or empty URL still shows its title as text; the panel does not break.

## Acceptance criteria
AC1 A relative URL (e.g. `/docs/a`, `docs/a`, `#sec-x`) renders as an anchor with that `href`.
AC2 An `http://` or `https://` URL whose origin equals the deck's own origin renders as an anchor.
AC3 An `http(s)` URL on any other origin (different host, port or scheme) renders as plain text, with the address visible, and no anchor.
AC4 Any other scheme (`javascript:`, `data:`, `vbscript:`, `ftp:`, `mailto:`, `tel:`, `file:`) renders as plain text with the address visible, including case/whitespace/control-character disguises such as `JaVaScRiPt:`, ` javascript:` and `java\tscript:`.
AC5 Protocol-relative URLs (`//evil.example/x`) and backslash tricks (`/\evil.example`) are NOT treated as relative; they render as plain text.
AC6 Empty, missing, non-string or unparseable URLs never throw; the helper reports "unsafe" and the caller shows the title (or nothing if there is no title) as text.
AC7 `src/safeUrl.test.ts` exists, runs under `npx vitest run src/safeUrl`, and passes; it covers every URL class in AC1-AC6.
AC8 Every place that renders a server URL (currently `src/ask/AskBox.tsx`) gets its link/text decision from `src/safeUrl.ts`; no component builds `href` from a server string directly, and none uses `dangerouslySetInnerHTML`.
AC9 A rendered safe link keeps `rel="noopener noreferrer"`; an unsafe URL is shown as text only, never as an `href`, and its address is not lost.

## States
- Empty: no sources, nothing rendered for links (the panel's existing empty message applies).
- Loading: unchanged - the existing panel loading state shows; this story adds none.
- Safe link: anchor with the URL; unsafe: plain text of title plus its address.
- NOT BUILT: unchanged - the panel shows its `why` from `built: false`; no links are rendered.
- Not permitted (403): unchanged - "not permitted for your role"; no links are rendered.
- Error (bad URL string): shown as text; no crash.

## Out of scope
- Changing any server endpoint or URL format.
- Allowing extra schemes or an allow-list of other hosts.
- Restyling links; existing styles apply.
- Fixing server data that contains bad URLs.
